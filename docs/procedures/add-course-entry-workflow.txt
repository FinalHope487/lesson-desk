新增科目／教材條目工作流程

觸發：使用者要求新增教材、專案或科目分類。
讀者：執行任務的 Agent；下列步驟除另列角色外均由執行 Agent 負責，依序使用前一步產物。每步的「輸入 → 操作 → 產物；閘門」也是下一步的依賴契約，未通過不得跳步；單篇失敗可依第五節處理其他獨立目標。
查核基線：2026-11-26。每次執行前重查來源程式、實際目錄、工具與授權；固定數字、映射、相容性及復原限制不是永久常數。既有 103 篇的瀏覽器基線曾通過，不代表新增教材已驗證。
目標：從使用者指定科目至實際畫面驗收，保留來源、完整性證據及既有教材，不擅自覆蓋或發布。

一、需求與授權

1. Agent｜使用者指定科目與目標 → 先讀 STATE.md、AGENTS.md，依 AGENTS.md〈開工時〉處理未決 QUESTIONS.md，再讀相關規格及本程序來源；盤點 manifest、正式 catalog、既有 ChatGPT 專案與範圍 → 現況與重複檢查結果；區分既有專案新增教材、既有科目新增專案、全新科目分類（見第六節）。
2. Agent＋使用者｜現況與初始需求 → 確認年級、冊別、課綱、教材來源與版本、章節、篇數、每篇範圍與深度、版型、公式、例題、習題、解答、圖片、圖表及互動要求 → 逐篇範圍清單及完整性／驗收規格；不清楚就先釐清。
3. Agent＋使用者｜範圍清單 → 提交目標 ChatGPT 專案（既有或待建立）、生成方式、匯入候選路徑、必要相容工作、預計修改範圍、驗收要求與不可逆事項；依 docs/procedures/questions.md 一次確認並記錄待決問題 → 使用者明確確認的任務；未確認不得建立對話或專案、登記 manifest 或修改教材／程式；提問程序所需且獲准的待決紀錄除外。沉默不算同意；未決部分按該程序停留 BLOCKED，僅推進不依賴答案的工作。
    額外付費（含訂閱額度）、開新 session、跨 session 傳訊、委派、覆蓋資料、改動相依、發布等依 AGENTS.md 取得各自必要授權；不可把教材範圍確認當成上述授權。若需變更公開契約（含新增科目及篇數），按 AGENTS.md:33 提出完整 docs/spec.proposed.md、登記 QUESTIONS.md，由使用者自行套用 docs/spec.md；不得自行編輯 spec。偏離規格或推翻決策依規則記錄 DECISIONS.md。範圍不足以辦理必要程序時，回報並等待授權。
4. Agent｜已核准任務 → 確認本次 Prompt、Project instructions／教材模板（若有）、生成環境、來源權限與至少一條可行完整匯入路徑；依第六節核對分類及必要稽核是否相容 → 可執行條件清單；現有證據未確認通用生成 SOP，不能假設 Prompt 或工具已具備。缺必要條件時停止相關工作；需改程式或擴大範圍則先取得相應授權。任何相容工作改檔前先完成第 8 步的可回復基準與保護措施（此時尚無新 ID 就先保存既有狀態，第 8 步再補 ID 對照，不重設原始基準）。改程式／測試前讀 docs/procedures/verification.md、docs/testing.md；若 Schema 改變或可能讀不到既有存檔，先走 docs/procedures/data-format.md，未獲必要切換授權不接上預設路徑。相容方案須在隔離環境通過適用驗證，依賴它的步驟才可繼續。
    若需委派生成、內容審查或 ChatGPT 審查，先依 docs/procedures/delegation.md 核對工具授權、額度及五項交接欄位；外部 agent 工具未列於 docs/project-rules.md 時不可直接使用。未授權則由主流程完成可做部分或按提問程序回報阻擋；委派回報由主流程獨立驗證。

二、生成和內容審查

5. 教材生成者｜核准範圍、Prompt、可用環境 → 選用已確認的既有專案，或按授權建立目標專案；逐篇生成完整教材對話 → 原始對話、標題及實際專案／對話 ID；生成未完成不得匯出。
6. 內容審查者｜原始對話與範圍清單 → 核對學科事實、章節、公式、例題、題目、解答及互動；獨立記錄可見 user／assistant 訊息數、ID（可取得時）、角色及順序、章節／題目數、圖片／圖表／題卡及必要互動元件與行為，保留可回查來源及完整性證據 → 逐篇內容驗收與來源基準；缺章、錯誤或未完成返回第 5 步，不能以匯出結果反推原始基準。
7. Agent｜已驗收對話 → 建立科目／專案名稱／projectId／conversationId／標題對照表 → 真實 ID 清單；projectId 符合 g-p- 加 32 位十六進位字元，conversationId 為 UUID 格式且不分大小寫唯一，專案 ID 與名稱對應一致、歸屬正確，名稱符合 builder 的檔名限制。現行 builder 以小寫 ID 建路徑與報告，exporter／接收器有精確字串比對，章節稽核亦要求原始 ID 字串一致；登記前確認實際來源 ID、manifest、路徑、報告及紀錄一致為小寫，不可任意改寫來源身分；不一致先驗證相容方式。未核對不得登記。

三、保存基線、登記及匯入

8. Agent｜已驗收 ID 清單與工作區 → 改檔前確認可回復基準（Git 狀態、manifest ID、正式 catalog、原始匯出檔、正式教材／媒體及版本、既有後加工成果），以 Git 及隔離暫存副本保留不可由 Git 還原的原始檔與使用者變更，不新增持久基線文件；確認 Node.js、.course-local/index.template.html、根目錄資源與寫入權限 → 基準及建置條件。任何全量 builder 操作（包括 exporter 內部 --local）先核對實際寫入範圍：可能遷移 legacy JSON、重建本機產物／報告及覆寫 course-library.html；未能證明現有資料安全或寫入未獲授權時，在含必要本機未追蹤資料的隔離副本操作，只採用核准差異。明確記錄本輪工作副本位置；manifest、原始匯出、資產、本機建置及報告均在同一副本或經核對同步的副本中操作，不混用不同狀態的報告。保留使用者既有變更，不以 reset 或覆蓋當作恢復。
9. Agent｜基線、ID 清單及分類相容結果 → 更新 chatgpt-course-export-manifest.json：既有專案增加 conversationId，新專案增加 name、projectId、kind、conversationIds；正式教材用 kind: "subject"，mixed 不納入 → 更新 manifest 與預期 ID 集合（既有＋核准新增）；ID 不重複、科目正確，新增分類尚未相容則停止。
10. Agent｜更新 manifest、基準及現有匯出檔 → 按第 8 步保護條件執行 node build-course-library.js --local，成功後讀 reports/course-library-report.json 的 expected、matched、missing → 新基準、已收錄 ID、待處理快照；expected 等於預期集合大小、missing 為其子集且舊 ID 未遺失。已存在且經第 6 步基準驗證完整的匯出可沿用，不要求每個新 ID 都在 missing；已收錄但內容不完整者另列待復原，不能靠 matched 判定完成。 --local 生成 .course-local/course-library-export.html、.course-local/course-content/ 等本機資料與報告，可能將 legacy JSON 寫至標準路徑，另將現有 index.html 複製為 course-library.html，不整合根目錄新教材。
11. Agent｜最新報告、來源基準及待處理快照 → 建立／續寫逐 ID 進度紀錄（可用 course-export-progress.jsonl 交叉核對）：ID、專案、來源路徑、輪次、嘗試次數、時間、結果與下一步；每次操作前記目標，操作後記結果 → 可續跑清單；初始快照保留不變，每次另更新仍缺 ID，未實際嘗試者不得算已嘗試。只記中繼資料，不將教材正文或帳號 ZIP 輸出到審查對話。
12. Agent｜待處理清單與可用來源 → 按下列路徑取得完整資料，逐篇或批次記錄實際結果 → 原始 JSON 與必要資產；來源、ID、完整性及覆蓋授權不符不得採用。
    A. 直接匯出：確認 Codex functions.exec 執行端具備 exec_command、apply_patch、mcp__codex_app__read_thread、PowerShell 及授權，所有內部命令與寫入指向同一受保護的工作副本。依 luna-course-export-runbook.md 第 2 節呼叫 runCourseExport(tools, { deferIds })；每次選一個尚缺的 targetId，deferIds = manifest 中所有其他 subject ID（精確字串，包含已收錄及非本輪目標），不只 missing，避免 canonical JSON 無 conversationId 或既有檔檢查失敗時誤抓別篇。保持 includeMixed=false，不並行。先確認目標標準及 legacy 路徑不存在，既有檔異常或不完整走第五節，不讓 apply_patch 的 Add File 覆蓋既有檔。現行 exporter 每頁 10 turns、每項 20,000 字元；拒絕截斷、附件、非文字或錯誤的部分資料。等結果及報告核對後才選下一 ID；若回傳其他 ID（含非目標檔案檢查錯誤），停止查明，不記為目標下載。
    B. 官方帳號 ZIP：有完整且合法取得的 ZIP、tar.exe 及足夠空間時，先在隔離副本執行 node build-course-library.js "<ZIP 完整路徑>"。此模式依 manifest 匹配 ID，建置 .course-local 與報告（亦同步現有根目錄 HTML），不直接重建正式 course-content/ 或 index.html；匹配 ZIP 紀錄優先於既有 course-exports JSON，可能覆蓋已復原資料，即使既有檔較新。核對差異，只採用核准的完整原始資料；不得把整批候選覆蓋正式工作樹。ZIP 內同 ID 多筆時選較新 update_time；不等於與本機比較新舊。
    C. 瀏覽器單篇接收器：先取得完整 transcript（現有腳本不提供網頁擷取）；確認目標在 manifest 與最新 missing、目標檔不存在、受保護工作副本具備同目錄 hard link 支援，再執行 node import-chatgpt-page.js。使用腳本輸出的本機隨機表單網址（127.0.0.1:48173，需可用），同來源表單送出 record JSON；只提交核准目標，不對外暴露接收器。接收器啟動時讀目標清單，清單變更需重新啟動；本輪接收結束停止服務。HTTP 201 只代表已寫檔；重建及核對報告後才算收錄。
    D. 完整單篇 JSON：使用者已持有可驗證的完整匯出檔時，不需重抓或使用接收器；核對實際 ID、格式與來源完整性後直接保存至第 13 步路徑，再重建。
    網站「匯入對話」只加入 Reader 記憶體，可預覽但不寫入正式資料庫，不能取代以上路徑。
13. Agent｜來源 JSON、ID 對照與資產 → 保存至 course-exports/<subject>/<project> [<projectId>]/<conversationId>.json（必要目錄須存在或建立），核對 ID、標題、科目及專案，保留原始資料 → 可建置紀錄；不得未授權覆蓋。直接匯出／單篇 transcript 使用 messages（id、role、text）；接收器要求 conversationId、字串 title、至少一則 assistant、每則 user／assistant 訊息有字串 ID 與非空文字、ID 不重複、HTTP 請求不超過 8 MiB。官方 ZIP 或完整單篇匯出可用 conversationId／conversation_id／id，可能為 mapping＋current_node 或其他 Reader 支援格式；按格式核對可見分支與訊息。標準路徑內的紀錄保留實際小寫 conversationId，以符合 exporter 與章節稽核的 ID 契約；若需轉換保留未改原始資料。
    Reader 能讀 mapping 不代表後續工具能讀：章節稽核直接讀原始及正式 record.messages；quiz-convert.js、leadin-fill.js 也依賴 messages。匯入前確認來源及正式候選能符合本次必需工具的格式契約；若不符，保留原始資料及資產，僅採用經逐篇完整性比對、可追溯且已驗證的相容轉換或經授權的工具調整。無可驗證方案即阻擋後續建檔／稽核，不將 mapping 原樣可顯示當作通過章節稽核。
14. Agent｜已保存紀錄及執行結果 → 每次操作後成功重建 --local（若 exporter 已成功重建則讀其最新報告），核對本次目標與實際檔案 → 單篇收錄狀態；exported 必須回傳相同 targetId 且不在最新 missing；complete／deferred 只在另有該目標收錄證據時算成功，不以狀態字串代替核對。ID 仍缺或報告過時則按第五節恢復。非本輪缺漏不得自行擴大匯出範圍。
15. Agent＋內容審查者｜原始對話、原始 JSON、本機產物及第 6 步獨立基準 → 比對可見訊息、順序、內容、章節、習題、解答、資產及必要互動，核對圖片檔存在與路徑（.course-local 建置優先讀 before-migration 的同名復原圖，與正式版可能不同） → 完整性結果與待復原清單；必要內容缺失不得進正式版。已收錄不等於完整。第一輪只有每個本輪核准的初始待處理目標都實際嘗試或證明由其他來源收錄才算走完；回報嘗試數、新增數、各科收錄數、失敗及待重試數。整批完成須所有預期 ID 仍在、expected = matched、missing 為空且本次教材完整；非本輪 ID 缺漏不擅自補，回報阻擋並待核准處理。不能以單篇成功宣告整批完成。

四、正式版整合及驗收

16. Agent｜完整本機教材、原始資產與第 8 步基線 → 只在隔離候選副本執行（若第 15 步使用的已是隔離副本，可沿用；否則另建隔離副本並核對更新 manifest、完整匯出、資產及必要相容程式均已同步） node build-course-library.js --pages 產生正式候選，核對 catalog、course-content、版本、媒體及所有舊教材 → 候選檔與差異；--pages 從原始匯出全量重建根目錄 index.html 與教材，可能覆蓋後加工成果。尚無已驗證的通用安全增量建置指令，本流程禁止在正式工作樹執行 --pages。
17. Agent＋使用者｜候選差異 → 確認保留舊教材的具體整合方式：隔離副本只納入核准的新教材、資產及目錄必要新增項，保留舊 catalog 條目與教材版本，核對 expected、projects、conversations 與資源引用；必要加工在隔離候選中完成並核對全部差異；從原始匯入副本移交的 manifest、匯出檔、必要資產及相容程式也納入候選核對，保留來源對照；依第 23 步的公開資料檢查核對候選內容，未通過不得納入正式教材 → 可回復、經核對的增量候選及授權；若不能證明整合安全、改動核准範圍外資料或可能覆蓋既有成果，停止並呈交差異，等待可驗證方案與所需授權，不能用授權代替技術驗證。
18. Agent｜通過第 17 步的候選 → 核對候選含已要求的題組、解答及前導題（quiz-convert.js、quiz-fill.js、leadin-fill.js 會寫教材及目錄版本；先在隔離副本核對適用格式、唯一目標與工具前置，避免全量加工及重複轉換）；先核對正式工作樹自基準以來未有衝突的新變動；核准後將 manifest、完整原始匯出及必要相容程式與教材候選一併移交至正式工作樹，僅整合最終核准差異 → 最終 course-content/<id>.js、必要 course-media、index.html；保留原始匯出、舊教材與正確版號。任何必要加工缺條件則停止，不能跳過已確認需求；正式根目錄不可再執行未驗證的全量寫入。
19. Agent｜最終根目錄產物 → 按第 8 步保護條件執行 node build-course-library.js --sync-local，核對 course-library.html 與 index.html 一致；確認匯入驗收報告來自相同 manifest／原始匯出狀態（若在隔離副本建置，核對後移交核准報告；必要時按第 8 步保護條件重新生成，不執行 --pages 覆蓋正式教材）；比對 manifest、最新報告及正式 catalog 的預期 ID 集合，逐一核對被 catalog 引用的教材與資產存在、ID、projectId、科目、標題及版本，確認舊資料未退化 → 靜態驗收結果；未引用的歷史殘留檔另列，不因此刪檔。 --sync-local 只複製 HTML，不會建檔。
20. Agent｜靜態驗收結果 → 確認現有 Playwright、Chrome／Chromium、Node.js 可用（必要時 PLAYWRIGHT_MODULE、CHROME_PATH 指向現有安裝），不要擅自安裝；稽核會寫 reports/，前後檢查 Git 狀態與報告差異，需唯讀基線時用隔離副本 → 瀏覽器環境與可追溯驗證基準；環境缺件先排除或回報阻擋。
21. Agent｜最終正式版、原始匯出及環境 → 依 docs/project-rules.md 與 docs/testing.md 原樣執行現行指定教材稽核及全站稽核（目前 node audit-course-browser.js --lesson=6af8b3dc-5ad4-83ee-9a6c-e98105cb5cd8、node audit-course-browser.js），另對每個新增 ID 執行 node audit-course-browser.js --lesson=<conversationId> --chapter-audit；涉及媒體／共用渲染時按確認範圍執行 node audit-course-browser.js --all-media --chapter-audit（不可與 --lesson 同時用）。若要求視覺化專項，依第六節單獨執行 → 最終版本稽核報告；各次一般瀏覽器稽核須 exit 0、issues 空、checks.catalog 等於預期篇數、checks.lessons 等於該次應載入篇數，章節／媒體證據符合需求；視覺化專項依其 summary 與 inventory 核對，不套用一般報告欄位。基線通過不能代替新增後驗證。--local 稽核讀根目錄 course-library.html 而非 .course-local 匯出版。

五、分支和恢復

- 範圍或生成規格不明：回第 2–4 步。內容錯誤、缺章或未生成完：回第 5–6 步。ID／分類不符：停在第 7–9 步，核對真實來源或分類相容性。
- 單篇 read_error、invalid_response、暫時性連線／逾時：記錄原因，第一輪先處理其他目標；第一輪後只重試仍未收錄者，最多再試兩次，同 ID 距上次失敗至少 60 秒。
- rate_limited：至少等 60 秒（服務明示更長則從其要求），再試同一 ID 一次；仍限流則整體暫停，恢復後由原位置續跑。帳號未授權、服務全面故障、progress_log_failed 或共通寫入／建置故障同樣先暫停；未實際下載者不得記為已嘗試。需使用者決定時按 docs/procedures/questions.md 登記，未授權不繼續該分支。
- invalid_cursor／empty：不接受部分或空資料，回查來源，按錯誤性質有限重試或換完整來源。truncated：若工具介面允許縮小每次讀取回合數，再試一次；仍超限或 unsupported_content／附件，改用完整 ZIP、單篇檔或已驗證的擷取，不能拿截斷資料補缺。
- file_check_failed、file_write_failed、operation_failed：查實際日誌、檔案、父目錄、權限；無法辨識原因則停止受影響路徑。接收器 HTTP 400／403／404：查格式、大小、來源、目前隨機路徑與目標清單；既有檔衝突先核對完整性，不擅自覆蓋。已收錄但不完整的紀錄不適用直接 exporter／接收器的正常缺漏路徑；先保留原始檔，在隔離副本取得完整替代來源並核對，需取代正式原始檔時取得明確授權，否則阻擋。
- catalog_build_failed、catalog_verification_failed 或仍在 missing：保留已取得 JSON，核對 manifest、ID、實際路徑、模板、必要資源、寫入權限及報告；本機問題排除後先重建，不重抓有效資料。只看到開始紀錄時先對最新報告與檔案，仍未收錄才重做該次。
- 圖片、題卡及互動資產遺失：回原始來源復原並重建／核對；現有 recover-course-pages.js、recover-course-images.js 分別限制目標數恰為 7、4，且受科目映射、來源與資產格式限制，不是假定可供新教材使用的通用工具；未能復原必要資產則阻擋。
- 完整來源未取得：優先使用已取得的官方 ZIP，不重複申請；無可用 ZIP 時核對完整單篇來源或已驗證擷取。若仍缺，將 ID 標為「等待來源」，保存進度及所需資料、受影響專案和件數；共通故障、使用者要求暫停或沒有可執行恢復步驟時，保留待辦並回報下一步，不無限重試、不自行結案。
- 正式候選改動舊資料：不採用候選版，保留基準，回第 16–17 步。依 STATE.md:24-30，既有功能退化則回退本輪、連續同類問題則停手重審契約；資料遺失、誤推送或誤對外發送則立即停止，由使用者決定回退方式，不自行修補。正式版找不到 ID：回第 16–19 步，不重複 --local。Offline HTML is out of sync：確認正式版後按第 8 步保護條件 --sync-local。稽核失敗依 log 定位資料或渲染層，修訂後重新驗證。
- 任務中斷：按最後通過閘門恢復；重新核對已確認範圍、來源 ID、manifest、最新報告、原始檔、基線及執行紀錄。有效且完整的 JSON 已存在則直接建置；已收錄但不完整仍須復原。正式版已變更則重新核對版本及稽核證據，不重複生成、匯出或盲目覆蓋。

六、分類與驗收相容性（第 1、4、9 步前置；每次重查）

- 既有專案沿用其 projectId；同科新專案用實際新 projectId。現行 exporter、builder、單篇接收器依專案名稱前綴「選修物理」→ 物理、「選修化學」→ 化學，其他正式專案預設數學；不符前綴的同科新專案也可能錯分。builder 以 manifest 推導 metadata 覆寫原始 JSON 的 subject，不能靠手填 subject 解除。

- runbook 舊基準為 14 subject 專案／103 篇，新增時以核准後 manifest 計算，不能沿用完成數字。一般 browser audit 動態讀 catalog；node audit-course-browser.js --visualization-audit 單獨執行，目前固定 103 篇，且只做靜態視覺化盤點，不是 live browser 驗收。若該專項為必要驗收，限制未解除即阻擋，不能自行停用；非必要才可明示不適用。該報告另含歷史觀察，不能算本次實測；核對 summary.catalogLessons、來源及 inventory 缺漏，並以實際互動驗收補足。
